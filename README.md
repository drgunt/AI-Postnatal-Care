# หมอท้อง ; AI Thai Postnatal Care

ระบบอัจฉริยะเชื่อมโยงการดูแลมารดาหลังคลอดแบบบูรณาการตามศาสตร์การแพทย์แผนไทย
> AI ไม่ได้วินิจฉัยแม่ แต่ AI รู้ว่าแม่ต้องการการดูแลอะไร และรู้ว่าเมื่อใดต้องส่งต่อให้คน

ต้นแบบนี้ (Phase 1–2: Digitalize + Rule-based AI Screening) แสดงแนวคิด 5 ชั้น **Collect → Screen → AI Analyze → Thai Traditional Medicine Care → Follow-up**

## ⚠️ ข้อสำคัญ
กฎความเสี่ยง ช่วงวันที่พิจารณาหัตถการ และฐานข้อมูลสมุนไพร เป็น **ตัวอย่างเพื่อสาธิต** ยังไม่ผ่านการ validate ทางคลินิก
ห้ามใช้ตัดสินใจรักษาจริง ก่อนใช้งานจริงต้องให้สูติแพทย์ ผดุงครรภ์ และแพทย์แผนไทยทบทวน รวมถึงประเมินด้าน PDPA

## ฟีเจอร์ในต้นแบบ (`web/`)
| แท็บ | สิ่งที่ทำ |
|---|---|
| หน้าแรก | น้องหมอท้อง (ไมค์พูดอาการ), กราฟระดับความเสี่ยง, เมนู 6 ช่อง, แถบล่าง หน้าแรก/ประวัติ/แจ้งเตือน/บัญชี |
| ประเมินอาการ | ฟอร์ม Digital Postnatal Passport → Risk Engine (🟢🟡🟠🔴) → TTM Decision Support (แถบระดับติดบนจอแบบ live) |
| ② AI หมอท้อง | แชทถามต่อก่อนตอบ ถ้าพบ red flag หยุดคำแนะนำทั่วไปและส่งต่อ |
| ③ Dashboard | จัดกลุ่มมารดาตามความเสี่ยง (ข้อมูลสมมติ) บุคลากรกด “รับทราบ” |
| ④ ตรวจสมุนไพร | ตัดสินจากกฎในฐานข้อมูล: ใช้ได้ / ควรปรึกษา / ไม่ควรใช้ (ไม่รู้จัก = ปรึกษาเสมอ) |
| ⑤ ติดตามอัตโนมัติ | ตัวอย่างข้อความ LINE OA Day 1/3/5/7/14/42 |

หลักความปลอดภัยที่เขียนไว้ในโค้ด: ระบบไม่เคยอนุมัติหัตถการเอง (สถานะมีแค่ พิจารณา/ยังไม่ถึงช่วง/ไม่แนะนำ), Red/Orange ปิดการแนะนำหัตถการ, ข้อมูลไม่รู้จักตกไปที่ “ปรึกษาบุคลากร”

## ข้อเสนอส่ง Hackathon (4 หน้า)
1. **Problem** — Journey “หลังคลอดแล้วหายไปไหน?” ตั้งแต่ออก รพ. ถึง 6 สัปดาห์
2. **Solution Architecture** — Data → AI Risk Engine → TTM Decision Support → Follow-up (วนกลับเป็น Real-world Data)
3. **หน้าจอจริง** — ใช้ภาพจากต้นแบบนี้: ประเมิน / แชท / Dashboard / ตรวจสมุนไพร / ติดตาม
4. **Innovation & Impact Canvas** — เดิม (รอผู้ป่วยมา) → ใหม่ (ติดตามเชิงรุก+จัดลำดับเสี่ยง) → ผลลัพธ์ (ตัวชี้วัด Access/Quality/Outcome/Efficiency) → ขยายผลระดับจังหวัด/ประเทศ
